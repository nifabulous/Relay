> **What this is:** A unified roadmap tracking the full lifecycle of the project — from the original backend remediation through the Relay frontend rebuild and beyond. Replaces the former `ENGINEERING_ROADMAP.md` and `IMPLEMENTATION_PLAN.md` (which are now archived as historical references).

**Last updated:** 2026-07-18 · **Tests:** 689 total (108 frontend + 11 E2E + 570 backend) · **Commits:** 35+

---

## Project identity

**Relay** is a responsive educational payment simulation. It teaches how cross-border payments work by letting users do each step — validate, verify, route, settle, track — and see the results.

**It is NOT a production payment system.** No real money moves. Every "payment" is simulated. Account numbers are `ACCT-` placeholders. The persistent label is **Educational payment simulation**.

### Who it's for

| Audience | What they get |
|---|---|
| Fintech engineers new to payments | Understand the domain before building payment features |
| Payment operations staff | Hands-on feel for BICs, Nostro/Vostro, SSI, VoP |
| Students / bootcampers | A concrete playground instead of abstract theory |
| Product managers | Understand what happens "under the hood" of a transfer |

## Architecture

```
swift-routing/
  app/                    FastAPI backend (Python 3.9+)
    main.py               App entrypoint, lifespan, static serving
    routers/              11 domain routers under /api/*
    services/             Domain logic (validator, routing, vop, prepare, etc.)
    models.py             SQLAlchemy 2.0 models
    schemas.py            Pydantic v2 schemas
    auth.py               API key auth (X-Admin-Key)
    static/               Legacy vanilla JS frontend (/learn, /ui)
    static/relay/         Built Relay React app (generated by Vite)
  frontend/               Relay React frontend (TypeScript 7, Vite 8)
    src/
      app-shell/          Shell, navigation, error boundary, routing
      design-system/      Tokens, Button, StatusChip, AsyncRegion, PaymentRoute
      api/                Typed client, Zod schemas, MSW test harness
      lib/persistence/    Versioned localStorage + legacy migration
      features/
        overview/         Adaptive home (selectPrimaryAction decision table)
        explore/          CommandSearch, BankDirectory, Glossary
        operate/          PreparePayment, Fees, Screening, ValueDate, STP, Tracking
        learn/            Curriculum (8 modules), prerequisite gating, progress
  tests/                  Backend test suite (570 tests)
  DESIGN.md               Canonical design contract (tokens, principles, anti-templates)
```

### Code review (4 expert reviewers)

After Tasks 1-10, a 4-reviewer checkpoint (Accessibility, Domain Expert, Design System Lead, Frontend Architect) identified 10 Critical (P0) and 11 Important (P1) issues — **all 21 fixed**:

**P0 fixes:** WCAG contrast tokens (4 failures → 0), `IntermediarySuggestion.bank` schema mismatch, removed frontend recommendation overrides (backend authoritative), `--color-on-action` token, removed colored card edges, error boundary, CommandSearch combobox ARIA, form `aria-describedby`, route-level code splitting, API client tests.
